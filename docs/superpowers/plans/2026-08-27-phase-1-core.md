# Phase 1 Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a working Phase 1 pnpm/Turborepo monorepo with Auth.js, transactional credits, BullMQ processing, synchronous image generation, asynchronous video generation, private TOS assets, SSE updates, Studio UI, and gallery.

**Architecture:** Thin Next.js route handlers call tested domain services; PostgreSQL remains the source of truth while BullMQ transports database job IDs. The worker claims jobs atomically, uses a typed injectable ModelArk client, persists provider state before polling, uploads completed media to private TOS, and publishes durable state changes over Redis. Fixed server-side generation profiles remain coupled to their flat credit costs.

**Tech Stack:** Node.js 24, pnpm 11, TypeScript 5.9.3, Turborepo 2.10.12, Next.js 15.5.24, React 19.2.8, Tailwind CSS 4.3.3, Auth.js 5.0.0-beta.32, Prisma 6.19.3, PostgreSQL 16, BullMQ 6.3.1, ioredis 6.0.0, Redis 7, and `@volcengine/tos-sdk` 2.9.1.

**Spec:** `docs/superpowers/specs/2026-08-27-phase-1-core-design.md`

## Global Constraints

- Work only in `D:\office\claude-custom`; it is the repository root.
- Implement only Phase 1. Do not create Phase 2–4 packages, routes, components, or deployment scaffolding.
- Do not add a major dependency outside the approved stack without user approval.
- Keep `User.email` required in Prisma.
- Image model defaults to `seedream-5-0-lite-260128` with cost 1 and fixed 4K, PNG, single-image output.
- Video model defaults to `dreamina-seedance-2-0-fast-260128` with cost 14 and fixed 5-second, 720p, 21:9 output.
- Model, size, resolution, ratio, duration, output format, and credit cost are never accepted from a job request.
- Any change to a default model, fixed generation profile, or flat credit cost must update the whole pair/profile and its tests together.
- Every BullMQ generation entry explicitly uses `attempts: 1`; the database claim prevents stalled image jobs from replaying `createImage`.
- Video generation is create-then-poll; image generation is one synchronous call with no poller.
- `ARK_API_KEY`, TOS credentials, OAuth secrets, and Resend credentials stay server-only.
- Docker is unavailable on this host; validate Compose statically and report that containers were not started.

```ts
export const IMAGE_PROFILE = Object.freeze({
  size: "4K",
  response_format: "url",
  output_format: "png",
  watermark: false,
  sequential_image_generation: "disabled",
} as const);

export const VIDEO_PROFILE = Object.freeze({
  resolution: "720p",
  ratio: "21:9",
  duration: 5,
} as const);

export function parseSubmitJobRequest(value: unknown): SubmitJobRequest {
  if (!value || typeof value !== "object" || Array.isArray(value)) throw new InvalidJobRequest("Body must be an object");
  const body = value as Record<string, unknown>;
  const allowed = new Set(["type", "prompt"]);
  if (Object.keys(body).some((key) => !allowed.has(key))) throw new InvalidJobRequest("Only type and prompt are allowed");
  if (body.type !== "image" && body.type !== "video") throw new InvalidJobRequest("Type must be image or video");
  if (typeof body.prompt !== "string") throw new InvalidJobRequest("Prompt must be a string");
  const prompt = body.prompt.trim();
  if (prompt.length < 1 || prompt.length > 2000) throw new InvalidJobRequest("Prompt must be 1-2000 characters");
  return { type: body.type, prompt };
}
```
